# Подготовка локального приложения Bitrix24

## Что уже реализовано

- прием установочных данных по адресу `/bitrix/install`;
- зашифрованное хранение токенов вне браузера;
- обновление пары токенов после ошибки `expired_token`;
- проверка установочного токена и прав администратора до сохранения OAuth-данных;
- привязка пункта «Автопарк» к размещению `LEFT_MENU`;
- личные уведомления `im.notify.personal.add` с постоянной очередью и повторными попытками.
- зеркало автомобилей в смарт-процессе через `crm.item.add/update` с постоянной очередью.

## Переменные окружения

```text
APP_BASE_URL=https://public-example.example
AUTH_MODE=bitrix
SEED_DEMO_DATA=false
BITRIX_CLIENT_ID=local.xxxxx
BITRIX_CLIENT_SECRET=xxxxx
BITRIX_ALLOWED_DOMAINS=company.bitrix24.ru
BITRIX_TOKEN_ENCRYPTION_KEY=случайная-строка-не-короче-32-символов
BITRIX_VEHICLE_ENTITY_TYPE_ID=1302
BITRIX_VEHICLE_FIELD_MAP={"plateNumber":"ufCrm10_100","model":"ufCrm10_101","status":"ufCrm10_102","currentDriverBitrixUserId":"ufCrm10_103"}
FILE_STORAGE_DIR=./data/files
FILE_MAX_BYTES=10485760
```

Секрет приложения и ключ шифрования нельзя добавлять в репозиторий. Для локальной разработки они задаются в `.env`, на сервере — в закрытых переменных окружения.

## Настройки в Bitrix24

- Тип: локальное серверное приложение с интерфейсом.
- Основной обработчик: `${APP_BASE_URL}/bitrix/app`.
- Обработчик установки: `${APP_BASE_URL}/bitrix/install`.
- Разрешения: базовые сведения о пользователе, пользователи, размещения, уведомления и CRM.
- Разрешенный домен должен совпадать с `BITRIX_ALLOWED_DOMAINS`.

## Зеркало автомобилей

`BITRIX_VEHICLE_ENTITY_TYPE_ID` — числовой идентификатор смарт-процесса автомобилей. Его можно получить методом `crm.type.list`.

`BITRIX_VEHICLE_FIELD_MAP` — объект JSON, где слева указано поле приложения, справа — поле карточки Bitrix24. Доступные поля приложения:

- `vehicleId`;
- `plateNumber`;
- `model`;
- `status`;
- `currentDriverBitrixUserId`;
- `startOdometer`;
- `startFuel`;
- `startAt`.

Фактические коды полей смарт-процесса нужно получить методом `crm.item.fields`. Если карта пуста, приложение все равно поддерживает заголовок карточки вида `госномер · модель`. После первого создания числовой идентификатор карточки сохраняется в `bitrix_item_id`; последующие операции обновляют эту же карточку.

## Вход сотрудников

При открытии `/bitrix/app` сервер проверяет переданный `AUTH_ID` методами `profile` и `user.admin`, создает закрытый серверный сеанс и больше не принимает идентификатор пользователя от интерфейса. Изменяющие запросы защищены отдельным токеном сеанса.

Перед проверкой сотрудника сервер находит сохраненную установку по `member_id` и сверяет ее домен с `DOMAIN`. Неизвестная установка или несовпадающий домен отклоняются до вызова REST API, поэтому данные разных порталов не смешиваются.

Саму установку и первый вход в новом портале должен выполнить администратор Bitrix24. Установочный обработчик сначала проверяет токен методами `profile` и `user.admin` и только затем сохраняет его в зашифрованном виде. Первый вошедший администратор становится администратором Autopark. Остальные сотрудники первоначально получают роль водителя; администратор меняет роли на экране «Пользователи».

Локальный переключатель ролей работает только при `AUTH_MODE=local`.

## Вложения путевых листов

Содержимое файлов хранится в `FILE_STORAGE_DIR` отдельно от базы данных, а в PostgreSQL записываются только метаданные и непрозрачный внутренний ключ. В Docker Compose каталог подключен как именованный том `autopark_files`.

Для рабочего сервера каталог файлов и база PostgreSQL должны попадать в одну согласованную политику резервного копирования. Значение `FILE_MAX_BYTES` нельзя задавать больше 10485760 байт без пересмотра серверных и инфраструктурных ограничений.
